# 영상 정지(freeze) 판정

## 현장 사례
RF 레벨(SNR 24 dB)은 정상인데, 모듈레이터 입력(위성/셋톱 수신기)의 신호가 끊겨 **마지막 화면 + "방송신호가 미약하여…"
안내문**이 멈춘 채 송출되던 채널이 있었습니다. RF만 보는 감시로는 잡을 수 없는 장애입니다.

## freezedetect가 놓친 이유
`freezedetect=n=-60dB:d=2`(기본에 가까운 값)는 프레임 간 평균 절대 차이(MAFD)가 n보다 작은 상태가 d초 이어지면 정지로 봅니다.
멈춘 화면이라도 헤드엔드 인코더가 다시 인코딩하면 차이가 0이 아닙니다.

| 측정 (480 폭 축소, 휘도 0~255) | 값 |
|---|---|
| 정지 화면 평소 차이 | 0.26 (= −60 dB와 거의 같음) |
| 키프레임(GOP)마다 튀는 잡음 | 0.4 ~ 1.2, 약 0.5초마다 |
| 정상 방송(KBS1) | 최소 3.2, 중앙값 8.2 |

키프레임 잡음이 정지 구간을 계속 끊어서 2초 연속 조건을 채우지 못했습니다.

## 방식: 프레임 차이 + 이동 중앙값
```sh
ffmpeg -f mpegts -i pipe:0 -map 0:v:0 -an -t <분석초> \
  -vf "scale=480:-2,format=gray,tblend=all_mode=difference,signalstats,\
metadata=mode=print:key=lavfi.signalstats.YAVG:file=<out.txt>" -f null - ; echo done > <out.txt>.done
```
- `tblend=difference` 뒤 `signalstats`의 `YAVG` = 앞 프레임과의 평균 휘도 차이(프레임마다 한 값).
- Python에서 `frame:… pts_time:` 줄과 `lavfi.signalstats.YAVG=` 줄을 짝지어 읽습니다.
- **9프레임(약 0.3초) 이동 중앙값**으로 키프레임 펄스를 제거 → 임계값 **1.0** 미만이 **2초** 이상 이어지면 정지.
  1.0은 정지(≤0.42, 원본 MPEG-2 기준)와 정상(≥3.2) 양쪽에서 3배 이상 떨어져 있습니다.
- 분석 구간이 짧으면(예: 2초) 최소 지속 시간을 구간의 90%로 낮춰야 판정이 가능합니다.
- 끝까지 정지면 "분석 끝까지"로 표시(실제 지속 시간은 그 이상).

## 수신 파이프라인에 넣는 법
- 같은 TS를 `tsp -P fork --ignore-abort`로 넘기고, 명령 끝에 `; echo done > file.done`(fork는 sh로 실행)으로 완료를 알립니다.
- 자동 스캔에서는 분석 시간 = lock 대기 시간. 스캔 체류는 "PSI 식별 + 캡처 + 분석 완료"까지.
- 디코딩은 CPU로 하되 480 폭으로 줄이고 흑백 변환하면 부하가 작습니다.

## 검증
- 합성 샘플: `testsrc2` + `freezeframes`(입력 2개 필요: `[0:v]split[a][b];[a][b]freezeframes=first=60:last=150:replace=60`)로
  "움직임 / 중간 3초 정지 / 끝까지 정지"를 만들어 서버가 쓰는 명령 그대로 확인.
- 실제 정지 채널은 수신을 끊지 않고 미리보기 스트림(mediamtx RTSP)에서 10초를 떠서 값 분포를 먼저 확인하고,
  가능해지면 원본 신호로 다시 확인(원본 0.42 vs 미리보기 0.26 — 비슷하지만 같지 않음).

## 주의
- 컬러바·정지 슬레이트·대기 화면처럼 원래 움직이지 않는 화면도 정지로 판정됩니다. 채널별 예외가 필요할 수 있음.
- 임계값은 해상도 축소·색 공간에 따라 달라지므로, 다른 장비에서는 정지/정상 샘플로 다시 재고 정하세요.
