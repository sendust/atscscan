# 헤드엔드 모니터링: 이력, 기준선, 경보, 알림, 스케줄

## 채널별 이력
- 측정이 끝날 때마다 `logs/channels/<mode>_ch<NNN>.jsonl`에 한 줄 추가(append-only, 파일 하나 = 채널 하나).
- 각 줄에 **그 시점의 기준선**도 함께 기록해 두면, 나중에 그래프에 기준선 변화를 그리거나 경보 근거를 설명하기 쉽습니다.
- 기존 통합 로그가 있으면 처음 실행 때 한 번 채널별 파일로 옮깁니다(디렉터리가 비어 있을 때만).

## 기준선
- **최근 lock 측정 N회(기본 7)의 중앙값**(SNR, 신호 품질). 평균이 아니라 중앙값이라 한두 번의 튐에 흔들리지 않습니다.
- 측정 수가 `min_baseline`(3) 미만이면 판정하지 않습니다(새 채널, 원래 안 잡히는 주파수는 경보 없음).
- 기준선은 **이번 측정을 넣기 전**에 계산합니다(자기 자신과 비교하지 않도록).

## 판정 규칙 (설정 가능)
| 조건 | 심각도 |
|---|---|
| 평소 lock되던 채널이 lock 실패 / 불안정(lock 비트만, TS 없음) | 위험 |
| SNR이 기준 − 3 dB 이하 (−6 dB 이하면 위험) | 주의 |
| 신호 품질이 기준 − 15%p 이하 | 주의 |
| 영상 정지 2초 이상 (기준선 없어도 판정) | 주의 |

수동 튜닝은 기본적으로 판정하지 않습니다(사람이 보고 있으므로). 자동·스케줄 스캔만.

## 경보 생명주기
- 같은 채널에 **해제되지 않은 같은 종류**의 경보가 있으면 새로 만들지 않음 → 매 스캔 반복 알림 방지.
- 조건이 바뀌면(lock 실패 → SNR 하락) 이전 종류는 해제하고 새 종류를 엽니다.
- 다음 측정이 정상이면 그 채널의 열린 경보를 **자동 해제**하고 복구 목록에 넣습니다.
- "확인(ack)"은 사람이 봤다는 표시일 뿐, 해제와는 별개(조건이 계속되면 열린 상태 유지, 재알림 없음).
- 저장: 원자적 쓰기(임시 파일 → `os.replace`), 최근 1000건 유지.

## 텔레그램
- `https://api.telegram.org/bot<token>/sendMessage`에 `chat_id`, `text`, `parse_mode=HTML` POST(urllib, 15초 타임아웃).
- **스캔 한 번에 한 통**: 신규 경보 + 복구 + 요약("lock 22/38 · 신규 경보 2 · 복구 1"). 채널마다 보내면 폭주합니다.
- HTML 모드라 `&`, `<`, `>` 이스케이프. 4096자 제한.
- 실패 사유(`description`, 예: Unauthorized)를 저장해 화면에 보여주면 설정 오류를 바로 압니다.
- 사용자 id: 봇에게 메시지를 보낸 뒤 `getUpdates`의 `message.chat.id`. 그룹은 음수 id.
- 토큰은 설정 파일(권한 600)에만 두고 API·화면·저장소로 절대 내보내지 않음.

## cron 스케줄러 (표준 라이브러리만)
- 5필드 `분 시 일 월 요일`: `*`, `a,b`, `a-b`, `*/n`, `a-b/n`, 이름(`mon`, `jan`), `@daily`/`@hourly`.
- 요일 7 = 0(일요일). **일과 요일이 둘 다 지정되면 OR**(cron 규칙). 둘 중 하나가 `*`면 다른 쪽만.
- 다음 실행 계산: 분 단위로 진행하되 월·일·시가 안 맞으면 크게 건너뛰기(1년 한도).
- 실행기: 5초마다 "분이 바뀌었는지" 확인 → 맞는 스케줄을 큐에 넣고, 작업 스레드가 **하나씩** 실행.
  이미 스캔 중이면 끝날 때까지 기다림. 같은 스케줄은 큐에 중복으로 넣지 않음.
- 화면에서 입력할 때 "다음 실행 5회"를 미리 보여주면 잘못된 식을 바로 알 수 있습니다.

## 그래프 (RF 추이)
- SNR(dB)과 신호 품질(%)은 **그래프 두 개**로(이중 축 금지), 기준선은 점선 + 직접 라벨, 경보 기준선(기준 − 3 dB),
  lock 실패 ✕·영상 정지 ❄ 표식은 색 + 기호로(색만으로 구분하지 않음), 두 그래프의 마우스 오버 동기화, 표 보기.
